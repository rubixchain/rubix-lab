Rubix Lab — SSH setup + node version check
============================================
This doc has two parts: setting up passwordless SSH from the controller to
every machine (a one-time thing, needed by every SSH-based tool: install,
restart, wipe, exec-update), and running node-versions.py once that's done.

Part 1 — SSH setup, in simple words
----------------------------------------
Right now, to run a command on another machine you have to type its
password every time. An SSH "key" fixes that: you make one key pair on the
controller, hand the public half to every machine once, and after that the
controller can log into any of them with no password.

There's a script that does this for you — setup-ssh.sh. It makes the key
(if you don't have one yet) and copies it to every machine listed in
controller/hosts.txt (fullnodes, faucet, explorer and pool alike):

    cd ~/rubix-lab/controller
    ./setup-ssh.sh

hosts.txt must already list the fleet with its roles — do NOT regenerate it
from an IP range, that would drop the roles (see hosts.txt.example).

It will still ask for each machine's normal login password once — that
part can't be automated away without storing the password somewhere
insecurely — but you only type the script name once instead of running
four commands per machine by hand. At the end it re-checks every machine
and tells you plainly which ones (if any) still need attention.

Safe to re-run any time, e.g. after adding new machines to hosts.txt —
machines that already have the key are just skipped over, nothing breaks.

Part 2 — get every node's Rubix version
----------------------------------------
Needs Part 1 done first. Also needs openpyxl (one-time):
    sudo apt install -y python3-openpyxl

Then, from the controller:
    cd ~/rubix-lab/controller
    python3 node-versions.py                    # every pool node
    python3 node-versions.py --include-fixed    # plus fullnodes and faucet nodes

Every node has its own copy of the binary (~/rubix-lab/nodes/node<slot>/),
so each one is read: one SSH call per machine runs `./rubixgoplatform -v` in
every node folder (it just prints the version and exits — doesn't touch the
running node). It prints one row per node with the version and the commit,
says "Uniform" or "MIXED" at the end, and writes controller/versions.xlsx.

The commit column is what proves a deploy landed - e.g. that every node,
fullnodes included, runs the build with the new faucet DIDs in its minter
allowlist.

If a machine shows "ssh failed: ..." in the Note column, Part 1 wasn't
completed for that machine — re-run setup-ssh.sh. "No such file or
directory" means that node was never installed (install-nodes.sh).
